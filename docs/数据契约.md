# 数据契约：build.py 读什么、怎么读

`dashboard/build.py` 是这套 vault 的专用解析器，不是通用静态站生成器。
它按**固定路径**去读**固定结构**的 Markdown。文件缺失不会崩，只会少一块内容并打 warning；
但结构写错会被静默跳过，所以对着这份契约核对格式最省事。

跑构建时加上 `2>&1 | grep warning` 就能看到所有没解析上的地方。

| `predictions/*.md` | 校样台、总台 | 预测/复盘全部为空 |

## 通用要求：YAML front matter

素材库、方法论、已发布内容里的每个 `.md` 都需要：

```yaml
---
tags: [标签1, 标签2]
type: 核心概念|金句|案例|爆款文稿|方法论|赚钱方法|低粉爆款|数据|选题|运营
status: 已收录|待筛选|持续更新|已完成
created: YYYY-MM-DD
---
```

`type` 和 `status` 的取值是枚举，写别的值会被归到「其他」。

## 各文件的结构要求

### candidates.md

每个候选是一个 `###` 标题，下面是 `- **key**: value` 的属性列表。
可识别的 key：`source` / `snapshot_at` / `tier` / `read_status` / `type` / `status` / `topic` / `note`。
紧跟其后的 `>` 引用块会被当作这条候选的代表句。

### 02-选题排期.md

按 `###` 分节，每节下面是一张 Markdown 表格。
表头需要包含「发布日」「类型」「选题」「状态」这几列（列序不限）。
「类型表现追踪表」那一节单独解析，表头需要「类型」「样本数」。

### 🔥每日热点雷达.md

每条信号是一个 Obsidian callout：

```markdown
> [!danger] 热点位圈1：标题
>
> **原文**：摘要正文
> **来源**：来源名
> **互动**：score 78
> **链接**：https://example.com/...
> **时间**：2026-01-10T09:00:00.000Z
>
> 你要讲的角度：...
> 钩子：【结果前置式】"..." → 挂 [[短视频开头方法论]] 结果前置式
```

标题里的 `热点位/方法论位/赚钱位/共鸣位` 前缀和圈码会被自动清洗掉。
`## 全量抓取` 区用扁平字段：`- 原文：` / `- 来源：` / `- 互动：` / `- 链接：` / `- 时间：`。
AIHOT 条目的 `✅` 会解析为 selected，末尾的 `` `industry` `` / `` `tip` `` 等会解析为 category。

### trends-history/YYYY-MM-DD.md

每条一行 `标题 | 来源 | 链接`，下面跟 `- 原文/摘要：` `- 互动：` `- 角度：` `- 钩子：`。
只留标题的话，自动热点库里会只剩一个没法判断的标题。

### predictions/*.md（结构最严，也最重要）

文件头是 `- **Key**: value` 列表，关键字段：
`Article ID` / `Script Path` / `Script Hash` / `Predicted At` / `Rubric Version` /
`Content Form` / `Confidence` / `Prediction Basis` / `Published at` / `Platform` / `URL` / `Video Folder`。

正文分段，段名必须精确：

- `## 预测 v1`（后续版本用 `## 预测 v2 (replaces v1; ...)`，**不要改写 v1**）
  - `### 7 维评分` 后面接表格，列为 `维度 | 分 | confidence | 理由`
  - `### Composite` 后面接代码块，写出算式
  - `### Bucket 押注` 后面接表格，列为 `Bucket | 范围 | 概率`
  - `### 反事实场景`、`### 关键校准假设` 用无序列表
- `## 复盘`
  - `- **复盘时间**:` / `- **抓取时间**:` / `- **数据来源**:` / `- **评论状态**:`
  - `### 实绩数据` 里用 `播放：4,200` 这样的「标签：数字」格式，可识别：
    播放 / 点赞 / 收藏 / 评论 / 分享 / 弹幕 / 完播率 / 2s 跳出率 / 5s 完播率 /
    平均播放时长 / 播放深度 / 封面点击率 / 赞播比 / 藏播比 / 评播比 / 分播比
  - `### 干扰`、`### 数据可信度`、`### 哪些预测被验证`（内部用 `**被验证**` / `**被推翻的**` 分隔）、
    `### 新观察`、`### Top 评论关键词`、`### Rubric 行动`

留存漏斗优先从复盘段自算，`04-数据统计/数据统计表.md` 只作 fallback。

### rubric_notes.md

评分口径的**唯一真源**。工作台从这里读维度定义、权重和 composite 公式，
然后跟 `CLAUDE.md` 的「7 维评分体系」段比对——不一致会在页面上报冲突（只读只报，不会改文件）。

## 输出

```
dashboard/
├── index.html  ideas.html  auto-hotspots.html  radar.html  pipeline.html
├── analytics.html  library.html  cheat.html  dbs.html
└── assets/data.json
```

**9 个页面各自内嵌了完整的 data.json**（单页约 700KB）。
这是设计如此——`file://` 直接双击就能看，不需要起服务。
代价是这些文件包含 vault 全量数据，**永远不要提交进 git**（`.gitignore` 已覆盖，CI 有检查）。

新增页面时，下面三处必须同时改，否则新页面永远不会被发布：

1. `dashboard/build.py` 的 `PAGES` 元组
2. `06-业务运营/cron/publish-workbench.sh` 的 `PAGES` 数组
3. `dashboard/tests/test_publish_workbench.py` 的 `PAGES` 列表

（这条不是洁癖——历史上就因为只改了一处，两个页面从未被发布出去。）
