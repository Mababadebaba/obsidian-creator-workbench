# 这个仓库是怎么维护的

本仓库是**单向导出的产物**，上游是作者本人的私有 vault。

```
私有 vault（唯一事实源）
   └── 导出器（清单驱动 + 脱敏 + 泄漏扫描）
          └── 本仓库
```

## 这意味着什么

- **直接改本仓库的代码不会被保留**——下一次导出会覆盖。
- 提 Issue 或 PR 完全欢迎：作者会把改动**手工回捡进上游**，再随下一次导出流回来。所以你的 PR 可能不是被 merge，而是以「同等内容出现在下一次导出」的形式落地，作者会在 PR 里说明。
- 示例内容（`01-` 到 `08-`、`predictions/`、`scripts/`、`videos/`、`trends-history/`、`candidates.md`、`audience.md`、`benchmark.md`）**全部是虚构的**，不对应任何真实账号或真实数据。
- `05-方法论沉淀/` 是真实的方法论正文，但其中引用的对标账号、真实案例数据在导出时已被匿名化或移除。

## 没有包含什么

- 作者的素材库、已发布内容、真实数据统计、预测与复盘记录
- 第三方项目：cheat-on-content（评分/预测/复盘 skill 本体）、第三方方法论 skill
- 任何构建产物：`dashboard/*.html` 和 `dashboard/assets/data.json` 内嵌整份 vault 数据，永久保持 gitignore

## 构建产物为什么必须 gitignore

`build.py` 会把整个 `data.json` 内联进每个 HTML 页面（单页约 700KB）。
一旦提交，等于把 vault 的全量摘要公开，且 git 历史里删不干净。
CI 里有一条检查专门守这件事。
