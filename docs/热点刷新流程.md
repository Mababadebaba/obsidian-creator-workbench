# 热点刷新流程

雷达页和自动化热点库的数据从哪来。**两步，都不需要定时任务、不需要 API key。**

```
第 1 步  python3 tools/fetch_trends.py     ← 抓原文，确定性，脚本干
第 2 步  对 AI 说「刷新热点雷达」            ← 做判断，非确定性，AI 干
第 3 步  cd dashboard && python3 build.py   ← 重建看板
```

为什么拆成两步：**抓取是确定性的，判断不是。**
「这条热点值不值得你做、该从什么角度切、开头怎么钩」这三件事依赖你的账号方向，
脚本自动生成只会产出模板话术——看着有内容，实际没法用。

---

## 第 1 步：抓原文

```bash
python3 tools/fetch_trends.py              # 抓取并写入
python3 tools/fetch_trends.py --dry-run    # 先看看抓到什么，不写文件
python3 tools/fetch_trends.py --sources aihot,follow-builders-x
```

它会把结果写进 `01-内容生产/选题管理/🔥每日热点雷达.md` 的 **「📡 全量抓取」** 区，
**不碰「⭐ 今日值得做的」区**——所以第 1 步和第 2 步谁先跑都不会互相覆盖。

### 内置数据源

| 源 | 说明 | 需要 key |
|---|---|---|
| `douyin-hot` | 抖音网页端实时热榜 50 条；保留排名、热度、榜单链接和事件时间 | 否 |
| `aihot` | AIHOT 中文 AI 热点；固定合并 `all=100` + `selected=50` 并按 id 去重 | 否 |
| `follow-builders` | Zara Zhang 维护的 AI Builder 聚合；X / Blog / Podcast 是独立子源 | 否 |
| `hackernews` | Hacker News 首页，带 points 和评论数 | 否 |
| `github` | 近 N 天新建、按 star 排序的仓库 | 否（未认证限 60 次/小时） |
| `rss` | 任意 RSS / Atom 地址 | 否 |

通用抖音模式默认开启抖音网页热榜，并用 AIHOT + follow-builders 补充站外资讯；HN / GitHub 作为可选备用。
改 `tools/trends-sources.json` 可增删源；其他垂类最简单的做法是复制 `rss` 配置，
把 `url` 换成你常看的媒体/博客 RSS，再把 `enabled` 改成 `true`。

AIHOT 会显式标注 `AI HOT · 原始来源`、category 和 selected 状态；
follow-builders 保留作者、原文、likes / RT / replies。Blog 或 Podcast 挂了只会记录该子源失败，不会拖垮 X 与 AIHOT。

抖音源使用抖音网页端公开热榜请求，不需要登录，但它不是开放平台承诺长期稳定的 OpenAPI。
如果抖音调整网页接口，抓取器会明确记录失败，不会用旧榜或模板伪装成实时数据。

### 抓不到时它怎么做

**如实记录，绝不编。** 某个源挂了，会在全量区写一条 warning 说明哪个源不可达；
所有源都挂了，直接退出且**不写文件**——避免用空内容盖掉上一次的抓取结果。

### ⚠️ 启用 HN 备用源时必须知道的限制：链接帖没有摘要

Hacker News 上大部分是**链接帖**，API 只返回标题、分数、评论数，没有正文。
所以这些条目的全量区里**不会有「原文」字段**（抓不到就省略，不编）。

这意味着第 2 步不能只看标题就写角度——**那等于猜**。选中一条 HN 链接帖时，
必须先真的把原文读一遍（AI 助手用它的联网能力读，或你自己点开），再写角度和钩子。
读不到的（域名不可达、需要登录）就**别进精选**，留在全量区备查即可。

GitHub 源没有这个问题：仓库描述会被完整带进「原文」字段。

## 第 2 步：让 AI 挑选并加工

在仓库目录下打开 Claude Code / Codex，说：

> 刷新热点雷达

它应该做的事（`CLAUDE.md` 里有完整约定）：

1. 读 `🔥每日热点雷达.md` 的「📡 全量抓取」区
2. **逐条过方向三问**（`05-方法论沉淀/选题方法论.md` 第 0 关）——方向外的一律不进精选，
   哪怕它再热
3. 从方向内的条目里挑出值得做的几条，类型尽量均衡
4. 每条补上：**你要讲的角度** + **钩子**（挂 `短视频开头方法论` 的 6 式之一，并标出用的哪式）
5. 写进「⭐ 今日值得做的」区
6. 同步写一份到 `trends-history/YYYY-MM-DD.md`（自动化热点库读这里）

如果你的 AI 助手不认这句话，把下面这段直接贴给它：

```
读 01-内容生产/选题管理/🔥每日热点雷达.md 的「📡 全量抓取」区。

逐条过 05-方法论沉淀/选题方法论.md 第 0 关的方向三问，方向外的直接排除并说明理由。
从方向内的条目里挑出最值得做的 6-8 条，5 个内容类型尽量均衡。

把选中的写进「⭐ 今日值得做的」区，格式：

> [!danger] 热点位圈1：标题
>
> **原文**：（从全量区照抄，不要改写）
> **来源**：
> **互动**：
> **链接**：
> **时间**：
>
> 你要讲的角度：（一句话，必须落在「用 AI 做出自己的东西」这个方向内）
> 钩子：【某某式】"具体的开头句" → 挂 [[短视频开头方法论]] 某某式

callout 类型按内容类型选：danger=热点 / example=方法论 / success=AI赚钱方式 / tip=共鸣类。

铁律：
- 原文、链接、互动数一律从全量区照抄，抓不到的字段就省略，不许编
- 方向外的条目留在全量区就好，不要为了凑数放进精选
- 不足 6 条就有几条写几条，并说明原因
```

---

## 第 3 步：重建看板

```bash
cd dashboard && python3 build.py
```

雷达页的「今日命中」会变成你选中的条数，「全量备查」会变成抓取总数。

---

## 想全自动？

可以，但**建议先手跑几天**——你需要先看清楚哪些源对你有用、方向三问在你这里怎么落地。
之后再包一层定时任务：

```bash
# macOS launchd / Linux cron，每天 20:00
python3 tools/fetch_trends.py && cd dashboard && python3 build.py
```

注意这样只自动化了第 1 步和第 3 步。**第 2 步（挑选 + 角度 + 钩子）如果也要自动化，
你需要一个能跑 LLM 的调度器**，而那部分本仓库没有包含——它依赖你自己的模型额度和运行环境，
且一旦额度断了整条链就会静默失效。所以默认设计是：**抓取自动化，判断留给人**。
