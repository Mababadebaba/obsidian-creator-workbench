# 内容生产 SOP（内容生产系统 × cheat-on-content 完整流程）

> 💡 两个系统不是并行的两套东西，而是**一条流水线上的两道工序**。本文是从想法到迭代的完整使用手册。
> 关联：[[选题方法论]] | [[短视频开头方法论]] | [[小红书标题方法论]] | [[02-选题排期]] | [[00-📊 内容生产看板]]

---

## 心智模型

- **内容生产系统 = 工厂**：造内容 + 存原料（素材库）+ 沉淀工艺（方法论）
- **cheat-on-content = 质检线 + 数据反馈**：发前预测、发后复盘、迭代质检标准（rubric）
- **两者共享三样东西**：选题（candidates）、稿子（script）、复盘数据。连接点就在这三处。
- **内容目标先分流**：`传播 / 获客 / 混合` 是目标层；`共鸣 / 教程 / 赚钱 / 方法论 / 热点` 是内容类型层，两者正交。

```
①选题进库 → ②选哪条 → ③写稿 → ④打磨 → ⑤定稿预测 → ⑥拍 → ⑦发 → ⑧复盘 → ⑨沉淀迭代
   ↑                                                                          │
   └──────────────────── 数据反哺，飞轮转起来 ←──────────────────────────────┘
```

### 传播线与获客线

| 目标 | 核心问题 | 写稿与验收 | 发布后主指标 |
|---|---|---|---|
| 传播 | 为什么会点开、看完、互动？ | 开头方法论 + 时钟理论 + 爆款/传播方法 + cheat-score | 播放、完播、互动、关注 |
| 获客 | 为什么正确的客户会相信并联系？ | 获客型短视频方法论（私有 · 未包含在开源仓库） | 有效线索、线索质量、预约、到场、成交 |
| 混合 | 如何既扩大触达又保持筛选？ | 传播结构打开流量口子，获客结构完成 KYC、证据与 CTA | 两组指标分开记 |

## 完整生命周期（一条内容的一生）

| 阶段 | 你说什么 | 系统 | 动作 / 落到哪个文件 |
|---|---|---|---|
| **①选题进库** | 「记录选题」 | 内容生产 | 灵感丢进 `00-选题记录` |
| | 「抓热点」 | cheat | `cheat-trends` 抓热点 → 写进 `candidates.md` |
| **②选哪条做** | 「推荐选题」 | cheat | `cheat-recommend` 按 rubric 排序 |
| | （同时人工过） | 内容生产 | `选题方法论` 4 维：搜索量/竞争度/时效性/变现 |
| | （再定目标） | 内容生产 | 标记 `content_goal: 传播 / 获客 / 混合`；获客稿写清客户、问题与承接 |
| | | **结合** | **选题 = 方向关 × 需求侧(4维) × 内容目标 × 执行侧(rubric排序)** |
| **③写稿** | 「深化选题」 | 内容生产 | **检索素材库** → 复用概念/金句/案例 → 生成稿 → 存 `01-待深化的选题/`（带 front matter + `[[链接]]`） |
| | （写稿参考） | cheat | `script_patterns.md` + `benchmark.md` 的对标 pattern |
| | （获客稿） | 内容生产 | 使用 `获客型短视频脚本模板`：项目 → KYC/旅程 → 问题 → 用户价值 → 方案 → 真实证据 → CTA |
| **④打磨质量** | 「起标题」 | 内容生产 | `小红书标题方法论` 出 3 个标题 |
| | 「优化开头」 | 内容生产 | `短视频开头方法论` 5 式打磨前 5 秒 |
| | （获客验收） | 内容生产 | 过 `获客型短视频方法论` 10 项检查；与传播评分分开 |
| | 「打分这篇」 | cheat | `cheat-score` 7 维盲评（HP 挂靠开头方法论） |
| | | **结合** | **分数 + 方法论一起指导改稿**，反复打分不留痕 |
| **⑤定稿预测** | 「启动预测」 | cheat | `cheat-predict` 写**不可篡改**盲预测 → `predictions/`（锁） |
| **⑥拍摄** | 「拍了」 | cheat | `cheat-shoot` 建 video folder，buffer +1；排期标 🎬 |
| **⑦发布** | 「已发布 [url]」 | cheat | `cheat-publish` 登记 URL/平台/时间 |
| | 「发布归档」 | 内容生产 | 文稿移到 `03-已发布内容/{平台}/`；排期标 🚀 |
| **⑧T+3d 复盘** | 「复盘 [path]」 | cheat | `cheat-retro` 粘评论+数据 → 对比预测vs实际 → 写 `rubric-memo` |
| | 「记录数据」 | 内容生产 | 数据回填 `短视频开头方法论`/`小红书标题方法论` 复盘区 + `02-选题排期` 类型追踪表 |
| | （获客数据） | 内容生产 | 另记有效线索、线索质量、预约、到场、成交；不以播放量代替获客结果 |
| | | **结合** | **一次复盘，喂两套系统的数据回填** |
| **⑨沉淀迭代** | 「沉淀素材」 | 内容生产 | 验证过的金句/概念/爆款结构入库，加链接 |
| | 「升级 rubric」 | cheat | 连续 3 次同向偏差 → `cheat-bump` 改公式 → 同步沉淀进 `05-方法论沉淀/` |

## 谁负责判断什么（别再混淆）

| 问题 | 谁回答 |
|---|---|
| 这个选题有没有人搜、竞争大不大、能不能变现？ | **内容生产**（选题方法论 4 维） |
| 这稿子写得好不好（钩子/情绪/金句/叙事）？ | **cheat**（rubric 7 维） |
| 这稿子能不能吸引并筛选正确客户？ | **高客单获客方法线**（项目 / KYC / 用户价值 / 真实证据 / CTA 10 项检查） |
| 开头这 5 秒怎么写？ | **内容生产**（开头方法论 5 式） |
| 这条发出去大概什么流量档？ | **cheat**（predict 盲预测） |
| 哪个**类型**数据最好？ | **两者结合**（排期轮播实验 + retro 数据） |
| 这次为什么预测错了，标准要不要改？ | **cheat**（retro → bump） |

## 分阶段：囤货期 vs 发布期

### 🔨 囤货期（现在 → 2026 年 6 月下半月）

剪辑工作流仍在打磨，只跑流水线前半段，**不碰 ⑤预测**（预测要在发布前一刻做才有意义）：

```
记录选题/抓热点 → 沉淀素材把库填厚 → 深化选题展开候选 → 打分探索（无承诺）
```

囤货期最高杠杆的两件事：
1. **批量沉淀素材**——库越厚，「深化选题」威力越大
2. **深化候选**——把待补充选题展开成完整稿

### 🚀 发布期（下半月起）

整条流水线跑通，按 [[02-选题排期]] 的 5 类轮播（共鸣→教程→赚钱→方法论→热点），周一/三/五各一条：

```
③深化 → ④打磨+打分 → ⑤启动预测 → ⑥拍了 → ⑦已发布 → 等3天 → ⑧复盘 → ⑨沉淀
```

发到第 12-15 篇：⑧的类型追踪表告诉你哪类最容易火；⑨的 rubric 开始第一次校准（v0 → v1）。

## 关键纪律（来自 CLAUDE.md 双系统协作铁律）

1. cheat 打分 HP 时**必须挂靠 `短视频开头方法论` 5 式**，不另起炉灶
2. 选题评估 = **需求侧（选题方法论 4 维）× 执行侧（cheat rubric）**
3. **数据反哺**：retro 后回填方法论文件的复盘区；bump 后同步沉淀进 `05-方法论沉淀/`
4. 起标题用 `小红书标题方法论`，不跳过
5. 预测一旦写下**不可篡改**（hook 强制）；前 5 篇精度 ±50%，是数据采集不是决策
6. 获客方法目前是 **43 条样本归纳的对标假设 v0.2**；传播数据与获客数据分开记录，连续出现真实信号后再升级规则
